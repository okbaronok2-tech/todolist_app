## 1. 원칙

- 구현 위치는 `frontend/src/styles.css` 전역 CSS 1개다 (원칙 7.3). 값은 `:root` CSS 변수로 두고 컴포넌트는 변수만 쓴다.
- UI 라이브러리, CSS 프레임워크, 아이콘 폰트, 웹폰트 다운로드 없음 (PRD R-01, 원칙 3.5). 다크 모드 없음 (PRD 2.2).
- 상태는 색만으로 구분하지 않는다. CP-04 배지 글자가 항상 함께 있다. 색은 보조 신호다.
- 장식보다 격자. 네이버 캘린더처럼 흰 바탕, 1px 회색 선, 숫자는 왼쪽 위, 강조는 오늘 칸과 막대뿐이다.

## 3. 컴포넌트

### 3.1 버튼

| 종류 | 스타일 | 쓰는 곳 |
|------|--------|---------|
| 주 (`.btn--primary`) | 배경 `--c-primary`, 글자 흰색 | [로그인] [가입] [저장] [등록] [확인] [추가] |
| 보조 (`.btn`) | 배경 흰색, 테두리 `--c-border-strong`, 글자 `--c-nav-bg` | [이전] [오늘] [다음] [취소] [편집] [이름 변경] [메뉴] |
| 위험 (`.btn--danger`) | 배경 흰색, 테두리·글자 `--c-danger`. 대화상자 [확인]이 삭제이면 배경 `--c-danger`, 글자 흰색 | [삭제], CP-03 삭제 확인 |
| 비활성 (`[-삭제-]`) | 배경 `--c-neutral-bg`, 글자 `--c-text-disabled`, `cursor: not-allowed` | BR-13·17 기본 카테고리, 요청 중 버튼 |

높이 `--control-h`, 좌우 패딩 `--sp-3`, 글자 `--fs-md`. hover는 배경을 4% 어둡게(`filter: brightness(.96)`). 묶음 버튼(`[이전] [오늘] [다음]`)은 사이 간격 없이 붙이고 바깥 모서리만 둥글린다.

### 3.2 입력·선택 상자

- 높이 `--control-h`, 테두리 1px `--c-border`, 패딩 `0 var(--sp-2)`, 글자 `--fs-md`. 포커스 시 테두리 `--c-primary`.
- 오류 필드: 테두리 `--c-danger`, 바로 아래 `--fs-xs` `--c-danger` 메시지 (CP-02 필드 오류). 사전 안내(시작일 > 종료일)는 같은 자리에 `--c-text-muted`로 표시한다.
- 라벨: 데스크톱은 입력란 왼쪽 96px 고정폭, 모바일은 입력란 위 (와이어프레임 5장). `(필수)`는 라벨 뒤 `--c-text-muted`.
- 날짜 입력은 브라우저 기본 `input type="date"` 그대로다 (PRD 4.2). 스타일은 높이·테두리만 맞춘다.

### 3.3 CP-01 상단 메뉴

높이 48px, 배경 `--c-nav-bg`. 브랜드 `TodoList`는 흰색 `--fs-lg` bold. 항목은 `--c-nav-text` `--fs-md`, 현재 화면 항목은 흰색 bold + 밑줄. 항목 간격 `--sp-6`. 모바일은 오른쪽 `[메뉴]` 보조 버튼(흰 테두리), 열면 아래로 항목이 한 줄씩 48px 높이로 펼쳐진다.

### 3.4 CP-02 오류 메시지 영역

배경 `--c-danger-bg`, 왼쪽 테두리 4px `--c-danger`, 글자 `--c-danger` `--fs-md`, 패딩 `var(--sp-2) var(--sp-3)`, 위아래 여백 `--sp-3`. 와이어프레임의 `!!`는 표기 기호이며 화면에는 찍지 않는다.

### 3.5 CP-03 확인 대화상자

오버레이 `rgba(0,0,0,.4)`. 상자 너비 360px(최대 `90vw`), 배경 흰색, `--radius`, 그림자(2.3), 패딩 `--sp-4`. 제목 `--fs-lg` bold, 안내문 `--fs-md`, 버튼은 오른쪽 정렬 `[취소] [확인]`. 열리면 포커스는 [취소]에 두고 `Esc`로 닫는다.

### 3.6 CP-04 상태 배지

알약형: 글자 `--fs-xs`, 패딩 `2px var(--sp-2)`, `border-radius: 999px`, 색은 2.1 상태 매핑. 캘린더 축약 배지 `<전> <진> <완> <초>`는 같은 색에 글자 한 자, 패딩 `0 4px`.

### 3.7 캘린더 (WF-05)

도구줄: 왼쪽에 묶음 버튼 `[이전][오늘][다음]`과 기간 글자(`--fs-lg` bold), 오른쪽에 분절 버튼 `[월][주][일]`. 활성 뷰는 주 버튼 스타일, 나머지는 보조. 모바일은 두 줄 (와이어프레임 5장).

월·주 뷰 격자:

- 7열 균등, 월 뷰 6행. 선 1px `--c-border`. 칸 최소 높이 96px, 내용에 맞춰 늘어난다 (할일 개수 상한 없음, PD-02).
- 요일 머리글: 배경 `--c-surface`, `--fs-sm`, 높이 32px. 일요일 `--c-danger`, 토요일 `--c-primary`, 나머지 `--c-text-muted`.
- 날짜 숫자: 칸 왼쪽 위, 패딩 `--sp-1 --sp-2`, `--fs-sm`. 이웃 달 날짜 `--c-text-disabled` (와이어프레임의 `(10-26)` 표기). 요일 색은 날짜 숫자에도 적용한다.
- 오늘 칸: 배경 `--c-primary-bg`, 날짜 숫자 `--c-primary` bold (와이어프레임의 `*`).

할일 막대 (네이버 월·주 뷰의 종일 일정 표시 방식):

- 조회 데이터는 그대로다 (BR-33: 겹치는 모든 날짜에 포함, BR-36: 완료 포함·필터 없음). 그리는 방법만 바꾼다. 같은 행(주) 안에서 시작 칸부터 종료 칸까지 이어진 막대 하나로 그리고, 행 경계에서 끊어 다음 행 첫 칸부터 다시 잇는다. 조회 기간 밖에서 시작·종료하면 행의 첫·끝 칸에서 잘린다.
- 막대: 높이 20px, `border-radius: 2px`, 왼쪽 테두리 3px 상태색, 배경 상태 배경색, 글자 `--fs-xs` `--c-text`, 패딩 `0 var(--sp-1)`, 내용 `<진> 제목` 한 줄 말줄임(`text-overflow: ellipsis`). 막대 사이 세로 간격 2px.
- 줄(lane) 배정: 행 안에서 시작일 빠른 순, 같으면 id 순으로 위에서부터 빈 줄에 넣는다. 그러면 US-14 표의 칸별 할일 집합이 그대로 나온다.
- hover: 배경 4% 어둡게, `cursor: pointer`. 클릭하면 SC-04 편집 (와이어프레임 WF-05). 드래그·칸 안 생성 없음 (D-12).
- 모바일 월 뷰: 막대 대신 상태색 6px 점. 5개 이상이면 점 4개 + `+N` (`--fs-xs`). 상태 구분은 주·일 뷰에서 본다 (PRD 4.3).

일 뷰:

- 데스크톱은 날짜 머리글 아래 할일을 한 줄씩 전폭 막대로 쌓는다. 막대 안에 `<진행중> 제목`, 오른쪽에 `기간  카테고리`(`--c-text-muted`). 할일 기간이 그 날짜보다 앞서 시작하면 막대 왼쪽 끝에 `‹`, 뒤로 이어지면 오른쪽 끝에 `›`를 `--c-text-muted`로 둔다 (네이버 일간 뷰).
- 모바일 주·일 뷰는 날짜별 세로 목록이며 각 항목은 전폭 막대 한 줄이다 (와이어프레임 WF-05 모바일 주 뷰).

빈 캘린더는 격자만 보이고 안내문이 없다. 로딩은 격자 자리에 `불러오는 중...` 한 줄 (`--c-text-muted`).

### 3.8 CP-05 할일 행, 표

- 데스크톱 표: 머리글 배경 `--c-surface` `--fs-sm` `--c-text-muted`, 행 높이 40px, 행 선 1px `--c-border`, hover `--c-surface`. 체크 상자는 기본 요소를 `accent-color: var(--c-primary)`로 쓴다.
- 완료 행: 제목 `--c-text-muted`. 취소선은 쓰지 않는다 (상태는 배지가 말한다).
- 모바일 카드: 패딩 `--sp-3`, 아래 선 1px `--c-border`, 2줄 (와이어프레임 CP-05).

### 3.9 CP-06 빈 목록 안내

가운데 정렬, `--c-text-muted`, 위아래 패딩 `--sp-7`. `[등록]` 링크는 `--c-primary` 밑줄.

## 4. 반응형

- 기준점 768px 하나 (PRD 4.3). `@media (max-width: 767px)` 블록 하나에 모바일 차이를 모은다.
- 모바일: `--control-h` 40px, 폼 버튼은 전폭, 탭 대상은 최소 44×44px(완료 체크·[편집]·[삭제]·캘린더 막대 행). 캘린더 칸 최소 높이 56px.
- 데스크톱: 본문 `--page-w` 가운데 정렬. 표와 캘린더는 본문 폭을 다 쓴다.

## 5. 접근성 최소 기준 (PRD 2.2 비범위 안에서 구현 비용 없는 것만)

- 글자·배경 대비 4.5:1 이상 (2.1 상태 색 포함).
- 상태·오류는 글자로 전달한다. 색만 쓰는 신호 없음.
- 버튼은 `button`, 이동은 `a`. 포커스 링(2.3)을 없애지 않는다.
- 캘린더 막대는 `button`이며 접근 가능한 이름은 `제목, 상태, 시작일~종료일`이다.
- CP-03은 `role="dialog"` `aria-modal="true"`, 열릴 때 [취소]에 포커스, 닫히면 연 버튼으로 포커스 복귀.
